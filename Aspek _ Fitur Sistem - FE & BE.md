

# **Matriks Aspek dan Fitur Sistem (Front-End & Back-End)**

| Modul/Fitur Sistem | Sisi Peladen (Back-End / Pancar) | Sisi Klien (Front-End / Yoga) | Batasan Integrasi |
| :---- | :---- | :---- | :---- |
| **Arsitektur Utama** | Back-End menerapkan pendekatan Clean Architecture dengan susunan Handler-Service-Repository, dikembangkan menggunakan Go, dan dijalankan melalui orkestrasi Docker Compose. | Antarmuka dibangun dengan Next.js 16 melalui App Router, React 19, TypeScript, dan Tailwind CSS v4.  | Pemisahan arsitektur mutlak (*decoupled*); pertukaran data eksklusif via JSON RESTful API. |
| **Basis Data & Skema** | Skema basis data dikelola melalui migrasi PostgreSQL 16, dengan pemanfaatan kolom JSONB serta mekanisme soft delete melalui kolom deleted\_at.  | Klien hanya menggunakan data statis yang diterimanya dan tidak terhubung ke basis data lokal.  | *Front-End* tidak memiliki tabel *users* atau skema lokal apa pun. |
| **Autentikasi SSO (Keycloak)** | Peladen membaca klaim dari token JWT, menggunakan JWKS untuk pemetaan kunci publik, dan menerapkan kontrol akses berdasarkan peran (RBAC).  | Sisi klien mengarahkan pengguna ke proses masuk, membatasi akses halaman melalui route guards, serta menyimpan sesi menggunakan HTTP-only cookies.  | *Front-End* memfasilitasi sesi peramban; *Back-End* menolak permintaan API yang tidak memiliki *Bearer token* valid. |
| **Penyimpanan Otomatis (*Auto-Save*)** | Tersedia endpoint /notulen/:id/auto-save untuk menerima dan menyimpan payload ke JSONB sekaligus mencatat setiap snapshot sebagai riwayat.  | Otomatisasi simpan menggunakan custom hook useAutoSave, dengan debouncing 2.000 ms, throttling 5.000 ms, dan percobaan ulang secara bertahap.  | *Timer* asinkron murni dikendalikan peramban klien; peladen hanya menerima dan mencatat status akhir. |
| **Editor Naskah (*Rich-Text*)** | Struktur pohon JSON yang dikirim diterima oleh peladen, disanitasi, kemudian disimpan dalam basis data dengan dukungan transaksi. | Penyunting teks kaya menggunakan Tiptap v3 (ProseMirror), dilengkapi pengaturan binding antarmuka dan simulasi area pengetikan yang aktif saat diklik (click-to-focus).  | *Front-End* membangun objek model dokumen; *Back-End* mempertahankan persistensinya. |
| **Penyimpanan Berkas (MinIO S3)** | Back-End berperan sebagai Smart Storage Proxy: berkas diteruskan secara pass-through memakai io.Copy untuk menjaga kerahasiaan kredensial S3 sekaligus menghindari kendala CORS.  | Klien menyediakan tampilan galeri foto, pratinjau dokumen fisik melalui iframe, serta fitur unggah berkas ke endpoint /api/v1/storage/\*.  | Peramban klien tidak pernah berkomunikasi langsung dengan *port* internal S3. |
| ***Generator*** **Dokumen Resmi (PDF/DOCX)** | Peladen menghasilkan dokumen secara langsung dengan Go: PDF dibuat menggunakan gofpdf, sedangkan DOCX mengikuti standar OOXML/ECMA-376; keduanya mencakup penyusunan tata naskah.  | Antarmuka menyediakan kontrol untuk memulai unduhan, memilih format atau mode dokumen, serta mencetak langsung dari peramban dengan tata letak @media print.  | Perakitan kop surat, penempatan logo dinas, dan pembuatan blok kolom tanda tangan sepenuhnya dieksekusi oleh peladen. |
| **Presensi Mandiri & Kode QR** | Endpoint publik /api/v1/public/absensi disediakan untuk menerima presensi tamu tanpa autentikasi SSO Keycloak, lalu mencatatnya ke tabel kehadiran.  | Sisi klien menampilkan Dynamic QR Code dan halaman presensi yang dirancang dengan pendekatan mobile-first pada rute /absensi/\[id\]. | Keterbukaan API diisolasi ketat oleh peladen hanya untuk insersi kehadiran satu naskah spesifik. |
| **Integrasi Data OPD (e-Kinerja)** | Back-End menjadi perantara permintaan ke API kepegawaian eksternal dan menyimpan hasilnya dalam in-memory cache dengan TTL satu jam.  | Data yang diterima dari proksi Back-End ditampilkan melalui komponen Combobox interaktif yang mendukung pelengkapan otomatis.  | Klien terhindar dari isu CORS peladen eksternal berkat perantara proksi peladen internal. |
| **Pencarian, Filter & Laporan** | *Pencarian teks penuh memanfaatkan kolom TSVECTOR dan indeks GIN. Peladen juga menjalankan penyaringan berdasarkan OPD serta mengagregasi data untuk laporan CSV.* | Klien menyertakan Global Command Palette yang dapat dibuka dengan Ctrl \+ K, tampilan matriks rekap, serta grafik analitik yang dibuat menggunakan Recharts. | Eksekusi pencarian teks kompleks dialihkan ke indeks basis data; klien fokus memoles presentasi visual. |
| **Validasi Aturan & Formulir** | *Setiap payload permintaan diperiksa di sisi peladen menggunakan struct tags dari pkg/validator untuk memastikan validitas permintaan HTTP dan menjaga integritas data.*  | Pemeriksaan skema formulir dilakukan langsung saat pengguna berinteraksi, dengan bantuan React Hook Form dan skema Zod.  | Lapis pertahanan ganda: klien mencegat galat pengetikan secara visual, peladen mencegah injeksi skema yang cacat. |
| **Operasi Basis Data Tambahan** | Peladen menangani proses penyalinan templat naskah melalui endpoint /duplicate serta pemulihan data yang dihapus secara lunak melalui /restore.  | Klien menampilkan dialog untuk meminta konfirmasi, menyediakan kontrol pada halaman tempat sampah, dan mengarahkan pengguna ke halaman yang sesuai setelah tindakan selesai.  | Seluruh manipulasi rekaman data dalam jumlah masif dibebankan pada proses internal peladen. |
| **Pengujian Sistem** | *Pengujian API dilakukan dengan pendekatan black-box, terutama untuk mengevaluasi nilai batas (Boundary Value Analysis) pada setiap endpoint menggunakan Postman atau Insomnia.*  | UAT digunakan untuk menguji fungsi antarmuka, alur penggunaan, dan skenario tugas yang dijalankan oleh aparatur sebagai pengguna akhir. | Uji peladen menitikberatkan ketahanan kontrak data; uji klien menitikberatkan kualitas interaksi dan kepuasan fungsional. |
